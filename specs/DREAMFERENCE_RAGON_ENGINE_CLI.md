# ragon-engine: Command lines

Part of the ragon-engine specification; the index is [README.md](./README.md). Written on 2026-11-01 from the code (`src/serve/main.cpp`, `tools/*.cpp`, `src/core/engine.cpp`), which is the source of truth: when the two differ, the code is right and this document is behind.

Four programs are built from the repository (`CMakeLists.txt`): `ragon-serve`, the HTTP server; `ragon-run`, the offline generator and checker; `ragon-tokenize` and `ragon-template`, two small reference tools the Python test harness drives. The test binaries (`ragon-kernel-tests`, `ragon-stream-tests`, `ragon-prefill-tests`, `ragon-spec-tests`, `ragon-draft-guard-tests`, `ragon-sampling-tests`, `ragon-api-tests`) take no arguments. Every program parses its arguments by hand: an unknown argument prints `unknown argument …` and exits 2, a flag that needs a value and has none prints `… needs a value` and exits 2, and a missing required argument prints the usage line and exits 2.

## 1. `ragon-serve`

```
ragon-serve --model DIR [--host H] [--port P] [--served-model-name N] [--max-context N]
           [--draft DIR [--draft-block N] [--tree N] [--lookup 0|1|2] [--lookup-min N] [--draft-bf16]
                        [--draft-off-below X]]
           [--pretokenizer production|checkpoint] [--prefix-checkpoints N]
           [--graphs] [--pdl] [--attn-bulk] [--attn-prefetch N] [--keepalive-seconds N]
           [--prefill-bf16] [--sessions N] [--session-protect-seconds S]
           [--batch N] [--prefill-chunk-contended N] [--side-prefill N]
           [--host-reserve-mb N] [--admit-reserve-mb N] [--auto-size 1|0]
           [--repetition-detection P,p,R,K|off] [--repetition-report incomplete|completed]
```

| Flag | Default | What it does |
|---|---|---|
| `--model DIR` | required | The checkpoint directory: the safetensors, `config.json` and `tokenizer.json`. |
| `--host H` | `0.0.0.0` | The listening address. Every interface by default, as production's engine listens; Ragon's gate or the Docker network is the boundary, not this flag. |
| `--port P` | `8000` | The listening port. |
| `--served-model-name N` | the last path component of `DIR` | The id `GET /v1/models` reports and every response carries. Ragon's tools ask the server which model runs, so this must be the id the registry expects ([INTEGRATION §12](./DREAMFERENCE_RAGON_ENGINE_INTEGRATION.md)). |
| `--max-context N` | chosen at start (`--auto-size`); `65536` without it | The context length: `max_model_len` in `/v1/models`, the limit of `context_length_exceeded`, and the size of the KV and state allocations. Not given, it is the model's full context (`config.json`'s `max_position_embeddings`, 262,144 for Qwen3.8-27B), halved only when one session does not fit there. |
| `--vision on\|off` | `on` | The checkpoint's vision tower ([VISION §20](./DREAMFERENCE_RAGON_ENGINE_VISION.md)): 0.92 GB of weights, scratch for the largest image and the embedding cache, allocated at start. `off`: image parts render as `[image]` and `/model_info` says `has_image_understanding: false`. |
| `--vision-max-pixels N` | `16777216` | The processor's `max_pixels` (its `longest_edge`), production's; also sizes the tower's scratch (N / 256 patches). Lower it only knowingly: larger images then get fewer tokens than production gives them. |
| `--vision-cache-mb N` | `512` | The cache of encoded images (their embeddings, by image), reserved at start; a prompt that resumes inside an image or repeats one does not run the tower again. |
| `--jpeg-decoder gpu\|cpu` | `gpu` | JPEGs through nvJPEG, as production decodes them, falling back to libjpeg-turbo; `cpu`: libjpeg-turbo only. |
| `--draft DIR` | none | The DFlash2 drafter's checkpoint. Without it every request decodes plainly. |
| `--drafter ID=DIR` | none | Repeatable, with `--draft`, which is the drafter `general`: another drafter, resident from the start ([MULTI_DRAFTER §5.3](./DREAMFERENCE_RAGON_ENGINE_MULTI_DRAFTER.md)). The ids are lowercase letters, digits, `-` and `_`. A drafter whose shape differs from `general`'s is refused, and each one's weights count in the memory plan at start. |
| `--drafter-routes FILE` | none | A JSON object from workload (`work`, `ask`, `phone`, `swe-bench`, `night`, `general`, or `*` for the rest) to drafter id ([MULTI_DRAFTER §5.2](./DREAMFERENCE_RAGON_ENGINE_MULTI_DRAFTER.md)); an unknown workload or drafter refuses the start. Without it every request runs on `general`. |
| `--draft-block N` | `12` | Draft tokens per speculative step. The default follows production, which runs 12 since 2026-11-01 (measured +7% single-stream over the drafter's published block of 16; the owner's decision of 2026-11-01 made 12 the code default too). The M0 reference container on the development machine keeps 16 on purpose. |
| `--tree N` | `7` | Tree verification ([BACKLOG §19](./DREAMFERENCE_RAGON_ENGINE_BACKLOG.md) item 26): N of the drafter's candidates beyond the chain verified as a tree in the same pass, on one-stream steps of a full block (batches, lookup chains and `logprobs` requests take the chain). The default shape, on since 2026-11-03 (the owner's decision), is the chain's first 8 drafts plus 7 nodes at temperature 1.5 (16 rows); `0` verifies the chain alone. Exact (`ragon-run --spec-check`; `tests/tree_tests.cu`). `RAGON_TREE` overrides it, and `RAGON_TREE_T`, `RAGON_TREE_CHAIN`, `RAGON_TREE_W`, `RAGON_TREE_DEPTH` and `RAGON_TREE_MIN` set the rest of the shape (section 4). |
| `--draft-off-below X` | `1.5` | The drafter-off guard ([BACKLOG §19](./DREAMFERENCE_RAGON_ENGINE_BACKLOG.md) item 10, [SPECULATION §10](./DREAMFERENCE_RAGON_ENGINE_SPECULATION.md)): a session whose running mean of tokens per speculative step (accepted drafts + 1, an EMA over about 16 steps, after 16 steps of warm-up) falls below X decodes one plain row per step with no drafter pass, probing the drafter with one speculative step after every 16 plain ones until the mean is back at X + 0.25. A plain step's session takes it alone, outside a batch. It applies to greedy requests, whose output is token for token the same; `RAGON_DRAFT_OFF_SAMPLED=1` extends it to sampled ones (same distribution, other tokens). `0` turns the guard off. `RAGON_DRAFT_OFF_BELOW` overrides it and `RAGON_DRAFT_ON_MARGIN` sets the 0.25. Counted in `/spec_stats` (`drafter_off_steps`, `drafter_switches`) and `/metrics` (`ragon:drafter_off_steps_total`, `ragon:drafter_switches_total`). |
| `--draft-bf16` | off | The drafter's fc and conv kernel projections in BF16 as its checkpoint has them, instead of the NVFP4 copies rounded at load ([BACKLOG §19](./DREAMFERENCE_RAGON_ENGINE_BACKLOG.md) item 33; the copies are the default since 2026-11-03, the owner's decision). Only the drafter's proposals change, so only acceptance can move: the verify decides every token either way. The copies are bit for bit `bench/quant/drafter_variants.py --nvfp4-copy`'s (`ragon-stream-tests --nvfp4-oracle DIR`); the fc keeps its BF16 original for the prompt's chunks over 32 rows, the conv projections do not. `RAGON_DRAFT_NVFP4` overrides it. |
| `--lookup 0\|1\|2` | `1` | The context-lookup draft source ([SPECULATION §10](./DREAMFERENCE_RAGON_ENGINE_SPECULATION.md)): 0 off; 1 shadow (proposed and scored afterwards against what was generated, counted in `/spec_stats`, never verified); 2 auto (verified instead of the drafter's chain when the match is at least `--lookup-min` tokens long, and the drafter's pass is skipped), as `Engine::Options::lookup_mode` has it. |
| `--lookup-min N` | `8` | The shortest match the lookup accepts. |
| `--pretokenizer production\|checkpoint` | `production` | The pre-tokenizer pattern: production's (how SGLang tokenizes this checkpoint) or the checkpoint's own `tokenizer.json` pattern. Any other value exits 2. |
| `--prefix-checkpoints N` | `8` | How many shared-prefix state checkpoints the engine keeps ([SESSIONS §11](./DREAMFERENCE_RAGON_ENGINE_SESSIONS.md)). |
| `--graphs` | off | Each speculative step's draft, verify and commit run as captured CUDA graphs (M3). Needs a drafter; refused, with a notice, while `RAGON_PROFILE` or `RAGON_KSPLIT` is set. |
| `--pdl` | off | Programmatic dependent launch for the rows path's kernels (M3). |
| `--attn-bulk` | off | The rows path's attention loads its tiles with bulk copies (M3). |
| `--attn-prefetch N` | `2` | How many KV tiles ahead the rows path's attention prefetches into L2; 0 switches it off (M3). |
| `--keepalive-seconds N` | `15` | How often a streamed request that has produced no token yet (waiting in the queue, or in prefill) is sent a keep-alive, so a client with an idle timeout keeps the stream: a `response.in_progress` event on `/v1/responses`, an SSE comment line on the chat and completions routes ([API §3, §4](./DREAMFERENCE_RAGON_ENGINE_API.md)). 0 switches them off. `RAGON_KEEPALIVE_SECONDS` overrides it. |
| `--sessions N` | chosen at start (`--auto-size`); `2` without it | Resident sessions, each with its own BF16 KV cache, DeltaNet and conv state and drafter context (about 4.8 GB each at 65,536 tokens of context), all allocated at start (M4 stage 1, [drafts/M4 §1](./drafts/M4-sessions-and-batches.md)). A request runs in the session it extends (its `prompt_cache_key`'s session looked at first, the token prefix deciding), else in a new session that takes a free slot or evicts the least recently used one. `sglang:max_total_num_tokens` reports sessions × `--max-context`. Not given, it is as many as fit at the context, at most 32 (`kAutoSessionsCap`), by `--auto-size`. |
| `--session-protect-seconds S` | `30` | A session bound with a `prompt_cache_key` whose last request ran less than S seconds ago is never evicted: a new session's request waits in the queue (`sglang:num_queue_reqs`) while requests that continue a resident session run (M4 §7 question 6). Sessions without a key are protected only while a request of theirs runs or waits. 0 turns protection off. The default was 180 s in stage 1; 30 s by the owner's decision of 2026-11-01. |
| `--batch N` | the sessions when they are chosen at start; `2` otherwise | Requests that run at once, each in its own resident session (at most `--sessions`; M4 stage 2, [drafts/M4 §3](./drafts/M4-sessions-and-batches.md)). The engine thread interleaves them: the running requests take turns, one prefill chunk or one decode step each, every unit in its own session's state, so each request's output is bit for bit what it is alone (`ragon-run --interleave-check`). Since stage 3, two requests that both decode speculatively take their steps together, one verify pass over both requests' rows (`Engine::speculate_batch`), again bit for bit each one's step alone (`ragon-run --batch-check`); a request that decodes plainly or has no room left for a full draft block takes its own one-row step. A request that continues a running request's session waits for it. 1 runs requests one at a time, as before stage 2. |
| `--prefill-chunk-contended N` | `256` | The prefill chunk, in tokens, while another request decodes (a multiple of 32 in [32, 2,048]; rounded down to a multiple of 32): each chunk runs between two of the decoding request's steps, so it bounds that request's step period during a long prefill (measured in drafts/M4 §6, stage 2). Chunk ends stay where a resumed prefill could start, so the state is the same (`ragon-run --chunk-check`). Without a decoding request the prefill runs in its full chunks of 2,048. |
| `--side-prefill N` | `40` | While another request decodes, a prefill runs in full chunks on a second stream on a green context of N SMs (`-1`: a plain second stream; `0`: off, the contended chunks of `--prefill-chunk-contended` alternate with the other request's steps instead), at the same time as the other request's steps ([drafts/M4-prefill-beside-decode](./drafts/M4-prefill-beside-decode.md)). Exact (`ragon-run --interleave-check --side-prefill N`). |
| `--host-reserve-mb N` | `16384` | Admission control at start ([BATCHING §5.6](./DREAMFERENCE_RAGON_ENGINE_BATCHING.md)): ragon-serve plans its footprint before allocating anything (the checkpoint's and the drafter's safetensors, the sessions' fixed parts and the KV page pool, or with `--kv-flat` the sessions' flat slots at `--max-context`, 4 GB of scratch, with images on the tower's scratch and `--vision-cache-mb`) and exits 3, saying by how much it is short, unless N MiB of `MemAvailable` would be left. 0 switches the check off (and with it `--auto-size`). `RAGON_HOST_RESERVE_MB` overrides it. |
| `--admit-reserve-mb N` | `8192` | While serving, a generation request that arrives while `MemAvailable` is below N MiB is answered HTTP 503 `host_memory_low` with `Retry-After`, before anything is queued or streamed (`ragon:memory_refusals_total`). 0 switches it off. `RAGON_ADMIT_RESERVE_MB` overrides it. |
| `--auto-size 1\|0` | `1` | Sizes the server from `MemAvailable` at start, by the same plan `--host-reserve-mb` checks ([BATCHING §5.6](./DREAMFERENCE_RAGON_ENGINE_BATCHING.md); the owner's decision of 2026-11-04): what is not given of `--sessions` and `--max-context` is chosen, the context first. The context is the model's full one, halved (in multiples of 2,048) down to 32,768 until the given sessions, or one session, fit; the sessions are then as many as fit at that context (with the page pool: as many as the pool holds at their full context, as flat; given sessions only need half of it, BATCHING §5.6), at most 32 (`kAutoSessionsCap`; P4e kept it at 4 while the prefix KV store was allocated after the page pool, P4f allocates it first and raised the cap, BATCHING §5.3), at least 1. The cap holds with `--kv-flat` too. Measured with the drafter on a 128 GB node (114 GB available, 2026-11-08): with nothing given, 3 sessions at 262,144 in both modes (the page pool 51.5 GB, 82.5 GB planned; flat 82.4 GB); with `--max-context 65536`, 4 in both modes at the cap of 4 (48.6 GB); since P4f (cap 32) about 12 paged on an empty node. `--batch`, not given, follows the chosen sessions. Given values are kept: `--sessions` alone chooses only the context, `--max-context` alone only the sessions, both the check as before. When nothing fits even one session at 32,768 the start check refuses it (exit 3). With `0`, `--host-reserve-mb 0`, or `MemAvailable` unreadable, the defaults are `--sessions 2 --batch 2 --max-context 65536` as before. Placement only: the server computes what the same `--sessions`, `--batch` and `--max-context` given by hand compute. On node-b with nothing else on the GPU (114.7 GB available) it chooses 3 sessions at 262,144 (four do not fit; BATCHING §3.5). `RAGON_AUTO_SIZE` overrides it. |
| `--kv-flat` (`--no-kv-pages`) | off: the KV page pool | The full-attention KV in a flat slot of `--max-context` positions per session, allocated at start, instead of the default: 64-position pages (4 MiB each) of one pool behind a page table per session ([BATCHING §5.3](./DREAMFERENCE_RAGON_ENGINE_BATCHING.md), P4; the default since P4e, 2026-11-08). Exact either way: only addresses change. The pool is what `MemAvailable` leaves after the plan, the prefix KV store's budget and `--host-reserve-mb`, at most `--sessions` × `--max-context` positions; a session costs its fixed part (~0.5 GB) and 64 KB for each position it holds. A fan-out's forks (a request's `n`) share their parent's pages in the pool; with `--kv-flat` each holds a whole slot (32 forks at 32,768: ~67 GB flat, ~2.1 GB and 0.5 GB a fork paged). `--kv-pages` is still accepted and changes nothing. `RAGON_KV_PAGES=0/1` overrides both. |
| `--kv-pool-mb N` | from the memory plan | The page pool's size in MB instead (P4b); refused at start when the plan with it does not fit, and refused with `--kv-flat`. |
| `--repetition-detection P,p,R,K` | `256,2,12,64` | The repetition stop rule's default ([API §9](./DREAMFERENCE_RAGON_ENGINE_API.md)): a request whose output (reasoning included) ends in a block of p .. P tokens repeated R times, or in one token repeated K times, ends with finish reason `repetition`; a request's `repetition_detection` overrides it field by field. `off` (or `0,0,0,0`) switches it off. |
| `--repetition-report incomplete\|completed` | `incomplete` | How `/v1/responses` reports a repetition stop: `response.incomplete` with reason `repetition` (what the `ragon` launcher's loop guard reads), or `response.completed` with `stop_reason: "repetition"` for Responses clients that retry an incomplete response (Codex 0.158 does, up to five times). |
| `--prefill-bf16` | off | The prefill's DeltaNet intermediates (the input norm's copy for the a/b projections, the in_qkv and in_z projections, the conv's output, the recurrence's output) kept in BF16 as production keeps them, instead of FP32 (B34; reports/M2-prefill.md §8 item 3). Not exact: a change of the prefill's numerics, so off until the checks of [MILESTONES §14](./DREAMFERENCE_RAGON_ENGINE_MILESTONES.md) pass (`bench/prefill_bf16_check.sh`). The decode and verify rows path is untouched either way. |

Startup prints the KV mode, `KV: paged (the default), page pool …` or `KV: flat slots (--kv-flat), S x C positions`, then `size: S sessions (…), batch B (…), context C (…); memory: available …, weights and scratch …, … a session, kept free …, planned …; requests refused below N MB`, each value marked `auto` (chosen by `--auto-size`), `given`, or `default` (with why no sizing ran, when it did not), then `loading DIR …`, then `loaded X GB of weights`, then with a drafter `drafter: X GB, block N, fc and conv projections NVFP4 (relative squared error E)` (or `BF16`); the server is ready when `GET /health` answers. The HTTP server runs two threads for the connections and one engine thread that runs up to `--batch` requests at once, interleaved one prefill chunk or decode step at a time ([API](./DREAMFERENCE_RAGON_ENGINE_API.md)); an idle connection is closed after 30 minutes; `SIGINT` and `SIGTERM` stop it. Each finished request logs one line to stderr: its session, prompt tokens (and how many were reused from a kept state), prefill seconds (wall, other requests' steps included), its chunks (and how many ran beside another request's decode) and its own tokens/s of compute, tokens generated, decode seconds and tokens/s, the finish reason, the number of passes and, speculatively, tokens per pass, and its step periods (start to start of its consecutive steps: mean and max, apart from those with another request's prefill chunk in between).

## 2. `ragon-run`

```
ragon-run --model DIR (--text T | --chat T | --ids 1,2,3 | --prompts-file F)
         [--max-tokens N] [--max-context N] [--temperature T] [--seed N]
         [--ids-out] [--prompt-ids-out]
         [--draft DIR [--block N] [--spec] [--spec-check] [--lookup 0|1|2] [--lookup-min N] [--draft-bf16]
                      [--draft-off-below X]]
         [--prefix-check [--sessions N]] [--chunk-check N] [--interleave-check [--prefill-chunk-contended N]]
         [--batch-check] [--drafter ID=DIR] [--switch-check]
         [--graphs] [--graph-check] [--pdl] [--attn-bulk] [--attn-prefetch N]
         [--prefill-bf16]
```

Loads the model and generates from a prompt; prints the text, the timings and, asked to, the token ids, for checking against a reference server (`bench/validate_v0.py`, `bench/agreement/`).

| Flag | Default | What it does |
|---|---|---|
| `--model DIR` | required | As for `ragon-serve`. |
| `--text T` | | A raw prompt, tokenized as given. |
| `--chat T` | | One user message, rendered through the chat template. |
| `--ids 1,2,3` | | The prompt as token ids. |
| `--prompts-file F` | | One JSON string per line, each a raw prompt; the checks below run over every prompt. |
| `--max-tokens N` | `64` | Tokens to generate per prompt. |
| `--max-context N` | `32768` | The context length. Half of `ragon-serve`'s default without `--auto-size` (65,536): the checker's prompts are short and the smaller allocation loads faster. |
| `--temperature T` | `0` (greedy) | Sampling temperature. `ragon-serve`'s default is the checkpoint's 1.0; the checker is greedy so its output can be compared token for token. |
| `--seed N` | `0` | Seeds sampling when the temperature is above 0 (0 draws a random seed). |
| `--ids-out`, `--prompt-ids-out` | off | Print the generated ids, or the prompt's ids, one list per prompt. |
| `--draft DIR`, `--block N`, `--lookup`, `--lookup-min`, `--draft-bf16` | none, `12`, `1`, `8`, off | The drafter and its settings, as `ragon-serve`'s `--draft`, `--draft-block`, `--lookup`, `--lookup-min`, `--draft-bf16`. |
| `--spec` | off | Decode speculatively with the drafter. |
| `--spec-check` | off | Greedy only: decode each prompt plainly, then speculatively, and check that the tokens are identical and that the recurrent state and the drafter's context after the speculative run equal a plain run's over the same tokens, bit for bit. Prints `spec check passed` or `SPEC CHECK FAILED`. With `--draft-off-below X` the speculative run is made three times: the guard off, the guard at X (a high X such as 100 trips it after its warm-up; use `--max-tokens 512` or more), and the guard at X with every probe switching the drafter back on and its next step off again; each must pass the same comparisons. |
| `--draft-off-below X` | `1.5` | As for `ragon-serve`: the drafter-off guard; with `--spec-check`, its check. |
| `--prefix-check` | off | Prefill each prompt after the one before it (resuming from a kept state or a prefix checkpoint), then again from scratch, and check that the DeltaNet and conv state and the next token agree (M2). With `--draft`, also decode 64 tokens speculatively (greedy) after each prefill and check that the tokens, the state, the steps and the accepted drafts agree (the drafter's context ring after a resume, M4). |
| `--sessions N` | `1` | With `--prefix-check`: N resident sessions, each prompt bound to one as `ragon-serve` binds a request, so each resumes from its own session's state, the shared checkpoint store, or another session's KV (M4 stage 1). |
| `--chunk-check N` | off | Prefill each prompt from a cold engine twice, in full chunks and in chunks of N tokens (what `ragon-serve` runs beside another request's decode), and check that the state and the next token are the same both ways; with `--draft` also the drafter's context ring after the prefill, bit for bit, and a 64-token speculative continuation's tokens, state, steps and accepted drafts. Exit 1 on a difference (M4 stage 2). |
| `--interleave-check` | off | With `--draft` and `--sessions 2`: the prompts in pairs (A, B), each first decoded alone (cold engine, `--max-tokens` speculatively); then A prefills and decodes while B prefills in chunks of `--prefill-chunk-contended` tokens (default 256) between A's steps, and the two take steps in turn, as `ragon-serve` interleaves two requests. Per sequence the tokens, the state, the steps and the accepted drafts must equal the run alone; greedy and sampled (`--temperature`, default 1, seeded by `--seed` or 1), and with the pair swapped. Exit 1 on a difference (M4 stage 2, [drafts/M4 §4](./drafts/M4-sessions-and-batches.md)). |
| `--batch-check` | off | With `--draft` and `--sessions 2`: the prompts in pairs (A, B), each first decoded alone (cold engine, `--max-tokens` speculatively); then the pair decoded as a batch of two (`Engine::speculate_batch`, one verify pass over both sequences' rows): both prefilled with the rows in the order [A, B] and [B, A], and one prefilling in chunks of `--prefill-chunk-contended` tokens while the other decodes, each way round. Per sequence the tokens, the state, the steps and the accepted drafts must equal the run alone; greedy and sampled (`--temperature`, default 1, seeded by `--seed` or 1). With `--graphs` both the runs alone and the batch replay step graphs (the batch path's own since M4 stage 4: the drafter over both blocks, the verify, each sequence's commit); without it both run eagerly. Exit 1 on a difference (M4 stage 3, [drafts/M4 §4](./drafts/M4-sessions-and-batches.md)). |
| `--drafter ID=DIR`, `--switch-check` | none, off | One more drafter, on which `--interleave-check` and `--batch-check` run their B. `--switch-check`, with one `--drafter`: each prompt decoded on one drafter and then, in the same session, its next request on the other, greedy and sampled, both directions; it fails when the tokens differ from a cold run on that drafter or (greedy) from plain decoding, when the target's state hash differs, or when the change was not counted. The rebuilt ring is reported, not required ([MULTI_DRAFTER §2.6](./DREAMFERENCE_RAGON_ENGINE_MULTI_DRAFTER.md)). |
| `--graphs`, `--pdl`, `--attn-bulk`, `--attn-prefetch N` | off, off, off, `2` | As for `ragon-serve`. |
| `--kv-flat` (`--no-kv-pages`), `--kv-pool-mb N` | off, from the sessions | As for `ragon-serve`: the checks run on the KV page pool by default (P4e); `--kv-flat` runs them on the flat slots (the flat arm of `--batch-check`'s paged-vs-flat comparison). The pool is `--sessions` × `--max-context` positions, or N MB. |
| `--prefill-bf16` | off | As for `ragon-serve`: BF16 DeltaNet intermediates in the prefill (not exact). The checks below run within the mode when it is on: `--prefix-check` and `--spec-check` must still pass bit for bit, which `bench/prefill_bf16_check.sh` verifies. |
| `--graph-check` | off | Decode each prompt speculatively twice from the same prefill, without and with step graphs, greedily and then sampling (top-k 20, top-p 0.95, seeded by `--seed` or 1), and check that the tokens, the recurrent state (bit for bit) and the step and acceptance counts agree. |

| `--vision-prompts F` | none | Image prompts ([VISION §20.8](./DREAMFERENCE_RAGON_ENGINE_VISION.md)): one chat-completions body per line, image parts as `data:` URLs or paths relative to F's directory, rendered and prepared as `ragon-serve` does; they take part in every check with their images. |
| `--vision-check DIR` | none | The tower against reference dumps (`bench/vision/reference.py`): decoding, resizing and patches against production's, the tower's output against transformers' in FP32 beside the references' own error; `--vision-bench` also times it. |
| `--greedy-out F`, `--force-file F` | none | The image agreement study's engine side (`bench/vision/agree.py`): plain greedy continuations with the prompt ids as production shows them, and teacher-forced top-20 log-probs over production's continuation. |

The three checks are the exactness tests the milestones' gates name ([MILESTONES §14](./DREAMFERENCE_RAGON_ENGINE_MILESTONES.md)); a failed check is reported and the exit status is 1.

## 3. `ragon-tokenize` and `ragon-template`

```
ragon-tokenize tokenizer.json < strings.jsonl
ragon-template < cases.jsonl
ragon-template --responses tokenizer.json [checkpoint] < bodies.jsonl
```

`ragon-tokenize` reads one JSON string per line and prints each one's token ids, for `bench/tokenizer_test.py`, which compares them with the reference tokenizer. `ragon-template` renders chat-template cases (one JSON object per line) to the prompt text the engine would see, for `bench/template_test.py`, which compares them with the patched Jinja template; with `--responses` it takes Responses API request bodies instead, converted the way `ragon-serve` converts them, tokenized with production's pre-tokenizer unless the fourth argument is `checkpoint`.

## 4. Environment variables

Read by the engine at start (`src/core/engine.cpp`) and by two kernels, and the last one by `ragon-serve`. **A variable set in the environment overrides the matching flag**, so a flag that seems to have no effect was probably overruled by one of these; they exist so a benchmark can switch a path without rebuilding the launch line.

| Variable | Effect |
|---|---|
| `RAGON_STEP_GRAPHS=0\|1` | Overrides `--graphs`. |
| `RAGON_PDL=0\|1` | Overrides `--pdl`. |
| `RAGON_ATTN_BULK=0\|1` | Overrides `--attn-bulk`. |
| `RAGON_ATTN_PREFETCH=N` | Overrides `--attn-prefetch`. |
| `RAGON_PREFILL_BF16=0\|1` | Overrides `--prefill-bf16` (also the way to switch it on in a program without the flag, such as `bench/agreement/ragon_force.cpp`). |
| `RAGON_PROFILE` | Set to anything: per-phase timing with a synchronization after each phase. Switches step graphs off (nothing may synchronize inside a captured step). |
| `RAGON_KSPLIT=N` | Split-K for the streaming GEMM; set and non-zero it allocates a buffer per step, which also switches step graphs off. |
| `RAGON_GEMM_SHAPE` | Selects the prefill GEMM tile shape (`src/core/prefill_gemm.cu`); a tuning switch for the benchmarks. |
| `RAGON_ATTN_CHUNK` | The decode attention's key chunk (`src/core/kernels.cu`); a tuning switch. |
| `RAGON_PDL_ATTN` | Programmatic dependent launch for the attention kernel alone (`src/core/kernels.cu`). |
| `RAGON_DRAFT_NVFP4=0\|1` | Overrides `--draft-bf16` (`0`: the drafter's fc and conv projections in BF16; `1`: the NVFP4 copies, the default). |
| `RAGON_TREE=N` | Overrides `--tree` (`ragon-run` too, which has no flag for it): `0` switches tree verification off. |
| `RAGON_TREE_T`, `RAGON_TREE_CHAIN`, `RAGON_TREE_W`, `RAGON_TREE_DEPTH`, `RAGON_TREE_MIN` | The tree's shape: the temperature of its priority over the drafter's lattice scores (default `1.5`), the chain's drafts kept in the block (`8`), children per node (`16`), the deepest level for extra nodes (no limit), and the summed path probability below which a step verifies the chain alone (`0`). |
| `RAGON_MK_FFN=0\|1` | The megakernel's stage 1 ([BACKLOG §19](./DREAMFERENCE_RAGON_ENGINE_BACKLOG.md) item 28): the rows path's FFN (gate\|up, SiLU-multiply, the FP16 copy, down) as one persistent kernel per layer. On by default since 2026-11-03; `0` takes the four kernels. Exact (bit for bit the four kernels). |
| `RAGON_MK_GDN=0\|1` | The megakernel's stage 2: a chain verify's DeltaNet mixer (input norm's output to the out-projection) as one persistent kernel per layer; a tree verify and a batched verify keep the graph path's mixer. On by default since 2026-11-03; `0` switches it off. Exact. `RAGON_MK_CHAIN` (default 24, the blocks that run a/b, the conv and the recurrence), `RAGON_MK_PREF_KB` (default 0) and `RAGON_MK_TIMES` (a timings store summarized on stderr at exit) are tuning and measurement switches. |
| `RAGON_MK_GDN_FUSED=0\|1` | A joint (non-tree) drafter verify of several sequences reads and writes each DeltaNet state once: the step's commit keeps only the conv state and the recurrence's inputs, and the next joint verify replays those rows before its own from the same registers (`gdn_recurrent_fused_seqs`); anything else that needs the state first flushes them. Needs the commit overlap and the batched state commit. On by default since 2026-11-10 (`=0` turns it off); exact (the replay runs the same per-token code). At 32 forks the DeltaNet stage goes from 69 to 51 ms per step and the warm span from 238 to 256 tok/s (2026-11-10). |
| `RAGON_KEEPALIVE_SECONDS=N` | Overrides `--keepalive-seconds` (read by `ragon-serve`, `src/serve/main.cpp`). |

Only the last is read by the HTTP layer; the rest of the server's behaviour towards clients is the flags' alone.
